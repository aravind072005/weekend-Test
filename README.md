# weekend-Test
1.Levels of Testing
       Levels of Testing are the different stages used to verify that software works correctly before it is delivered to the customer.

Unit testing  

       Tests individual components or functions of the application.
       Usually performed by developers.
       Objective: Ensure each unit works correctly.
Integration Testing

        Tests how different modules work together.
        Performed after Unit Testing.
        Objective: Find defects in the interaction between modules.
System testing 

          Tests the complete application as a whole.
          Usually performed by the QA (Testing) team.
          Objective: Verify that the entire system meets the specified requirements.
Acceptance testing 

           Performed by the customer or end users.
          Objective: Ensure the software meets business requirements and is ready for release.


2.Five Principles of Software Testing

    Testing Shows the Presence of Defects
 testing can prove that defects exist but cannot prove that the software is completely error-free.
2. Exhaustive Testing is Impossible
It is impossible to test every possible input and scenario.
 Testing should focus on important and high-risk areas.
3. Early Testing
 Testing should start as early as possible in the Software Development Life Cycle (SDLC).
 Early testing reduces the cost of fixing defects.
4. Defect Clustering
 A small number of modules usually contain most of the defects (80/20 rule).
 Testers should focus more on these defect-prone areas.
5. Pesticide Paradox
Running the same test cases repeatedly will eventually stop finding new defects.
- Test cases should be reviewed and updated regularly.
